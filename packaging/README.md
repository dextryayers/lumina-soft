# Packaging

Lumina builds one staged payload per platform and derives every installer from
that same payload. This avoids the classic bug where the MSI, the portable ZIP,
and the app contain different binaries.

> binaries, and both packaging scripts pass syntax checks. WiX v4, NSIS,

## Layout

```text
packaging/
  windows/
    build.ps1       Release build, staging, MSI, NSIS, portable ZIP
    lumina.wxs      WiX v4 per-user MSI definition
    installer.nsi   NSIS per-user setup and uninstaller
  linux/
    build.sh        Shared Linux staging, deb, rpm, apk, AppImage
    AppRun          AppImage entry point
    lumina.desktop  Desktop entry
    lumina.appdata.xml
    lumina.svg      Application icon
    completions/    bash, fish, and zsh completions for both binaries
```

Outputs go to `dist/` and are ignored by Git. Installed size, artifact size, and
checksums must be recorded in the release checklist.

## Windows

Requirements:

- Rust 1.85 or newer with the MSVC target
- WiX Toolset v4 (`wix` on `PATH`) for the MSI
- NSIS 3 (`makensis` on `PATH`) for the setup executable
- PowerShell 5.1 or newer

Build everything:

```powershell
.\packaging\windows\build.ps1
```

Build only the portable ZIP while iterating:

```powershell
.\packaging\windows\build.ps1 -SkipMsi -SkipNsis
```

Useful switches:

| Switch | Effect |
|---|---|
| `-SkipBuild` | Reuse `target\release` |
| `-SkipMsi` | Do not require WiX |
| `-SkipNsis` | Do not require NSIS |
| `-SkipPortable` | Do not create the ZIP |
| `-Version` | Override the workspace version |
| `-MsiVersion` | Override the four-part numeric MSI version |
| `-Arch` | Artifact architecture label, default `x86_64` |

The MSI is per-user and installs under `%LOCALAPPDATA%\Lumina` without
elevation. It creates a Start menu entry and registers an uninstaller. The NSIS
setup uses the same per-user location and preserves the user's configuration
during uninstall. The portable ZIP contains only the binaries and project
documents; it writes configuration to the normal per-user config directory.

Prerelease versions cannot be used directly as MSI versions. `build.ps1` maps
`alpha.N` to revision `N`, `beta.N` to `100 + N`, and `rc.N` to `200 + N`.
Pass `-MsiVersion` explicitly if the mapping would collide with an existing
release.

## Linux

Requirements:

- Rust 1.85 or newer
- `dpkg-deb` for `.deb`
- `rpmbuild` for `.rpm`
- `abuild` for `.apk`
- `appimagetool` for `.AppImage`

Build everything:

```sh
./packaging/linux/build.sh --all
```

Build selected formats:

```sh
./packaging/linux/build.sh --deb --appimage
```

Create only the shared staging tree:

```sh
./packaging/linux/build.sh --stage-only
```

The staging tree is `dist/linux-stage` and follows the Debian filesystem layout:
binaries in `/usr/bin`, desktop metadata in `/usr/share`, icons in the hicolor
theme, and completions in the bash, fish, and zsh vendor directories. Debian,
RPM, and AppImage builds use this tree. The APK target reuses it as well.

`VERSION`, `DIST`, `ARCH`, and `SKIP_BUILD` are environment overrides. Debian
versions replace the prerelease hyphen with `~`; RPM splits the core version and
the prerelease suffix.

If a requested tool is missing, the script reports the missing format and exits
non-zero after attempting the others. This is intentional: a release build must
not silently omit an artifact.

## Completions

The `lumina-send` completions are generated by the binary itself:

```sh
lumina-send --completions bash
lumina-send --completions fish
lumina-send --completions zsh
```

The committed copies are installed by Linux packages. Regenerate them whenever
the client's commands or flags change. `lumina` completions cover the CLI
surface in `crates/lumina-app/src/main.rs`.

## Versioning and signing

The version comes from `[workspace.package]` in the root `Cargo.toml`. Do not
duplicate it in a package script. The release tag must match the changelog
heading.

V0.1.0 artifacts are unsigned. Windows SmartScreen may warn, and Linux packages
are not signed by a distribution key. Checksums are published next to the
artifacts. Signing is a separate project and must not be implied by the presence
of a setup executable.

## Verification

Before publishing, run:

```sh
cargo xtask docs --check
cargo xtask release-check
```

Then execute the artifact rows in
[`docs/manual-test-matrix.md`](../docs/manual-test-matrix.md) on clean VMs.
`release-check` verifies metadata, not installation. A green metadata check is
not a release approval.
